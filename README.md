# FileLens

Русская программа для Windows 10/11 x64: показывает приложения и службы, использующие выбранный файл. Переносимый EXE включает .NET; установка и интернет для работы не нужны.

**Portable:** достаточно одного `FileLens.exe`. Установка программы и .NET не требуется; EXE можно хранить в любой папке или на флешке. При первом запуске встроенная среда извлекает служебные компоненты во временный каталог Windows.

**[Скачать готовую программу](https://github.com/Quake-Journey/FileLens/releases/latest)** — `FileLens.exe` или архив `FileLens-Win64.zip`. Контрольные суммы опубликованы рядом в `SHA256SUMS.txt`.

Исходники: [Quake-Journey/FileLens](https://github.com/Quake-Journey/FileLens). Изменения версий: [CHANGELOG.md](CHANGELOG.md).

## Запуск

Открой `FileLens.exe` (в каталоге исходного проекта он находится в `release`). Вставь полный путь в поле (кавычки из команды «Копировать как путь» допускаются) или нажми «Выбрать файл…». Нажми «Найти процессы» либо Enter. Файл также можно перетащить из Проводника: поиск начнётся автоматически.

Кавычки и пробелы по краям вставленного текста очищаются автоматически. Поддерживается формат Far Manager с кавычками только вокруг папки: `"C:\Program Files (x86)\MSI Afterburner\"RTCore64.sys` преобразуется в `C:\Program Files (x86)\MSI Afterburner\RTCore64.sys`. Пробелы и апострофы внутри имён сохраняются. Исправленный путь появляется в поле при начале проверки.

В таблице видны имя процесса, PID, способ использования и путь к EXE. Если файл используют несколько процессов, каждый появляется отдельной строкой. Для службы также показывается её имя, когда Windows передаёт эти сведения.

Выдели строку: «Расположение EXE» откроет программу в Проводнике, а следующая кнопка «Копировать путь» скопирует её полный путь в буфер обмена, без кавычек. Эти две кнопки относятся к выбранной строке; без выбора или при неизвестном пути они недоступны. «Копировать отчёт» копирует результат проверки целиком. Повторное нажатие «Найти процессы» обновляет снимок.

Если часть процессов недоступна, нажми «Запустить от администратора» и подтверди стандартный запрос Windows. Перетаскивание из обычного Проводника в окно с правами администратора может быть недоступно: используй ввод пути или выбор файла.

## Проверка из контекстного меню Windows

Открой **«Параметры» → «Добавить в меню»**. Для файлов появится пункт **«Проверить, кто держит файл»**. Регистрация выполняется для текущего пользователя и не требует прав администратора.

В Windows 11 пункт находится в **«Показать дополнительные параметры»**. В Windows 10 он отображается в обычном контекстном меню. Выбери один файл, нажми правой кнопкой и выбери этот пункт: FileLens откроется и сразу начнёт проверку.

Если окно FileLens уже открыто в этом сеансе Windows, файл проверяется в нём. Свёрнутое окно восстанавливается. При выборе нового файла во время поиска предыдущая проверка отменяется; проверяется новый файл.

Чтобы убрать пункт, открой **«Параметры» → «Удалить из меню»**. Программа остаётся Portable: регистрация меню необязательна и не копирует EXE в системные папки. Она привязывает пункт к текущему расположению EXE; после перемещения программы добавь пункт заново из новой папки. Перед удалением программы убери пункт меню.

Также поддерживаются параметры командной строки:

```powershell
.\FileLens.exe --register-context-menu
.\FileLens.exe --unregister-context-menu
.\FileLens.exe --check-file "C:\Folder\file.dll"
```

Интеграция использует собственный раздел `HKEY_CURRENT_USER\Software\Classes\*\shell\FileLens.CheckFile`. Передача выбранного файла между экземплярами ограничена текущим пользователем и сеансом Windows.

## Значение результата

- «Удаление блокируется»: открытие файла с правом DELETE возвращает конфликт совместного доступа.
- «Доступ для удаления открыт»: такое открытие удалось. Это проверка доступа на текущий момент, а не гарантия успешного удаления.
- «Нет доступа для удаления»: Windows отказала в доступе; причиной могут быть права, защитное ПО или особенности файла.
- «Атрибут «Только чтение»»: обнаружен соответствующий атрибут, который также может мешать удалению.
- «Файл загружен в процесс»: DLL или EXE загружен как модуль; это может мешать удалению даже при успешном открытии с правом DELETE.

Программа не удаляет файлы, не закрывает чужие дескрипторы и не завершает процессы. В списке могут быть программы, допускающие удаление открытого файла. Процессы и блокировки могут измениться сразу после проверки. Программа принимает один файл; поиск внутри папки не выполняется.

## Как работает поиск

Поиск объединяет поддерживаемый Windows Restart Manager, дополнительный нативный запрос списка PID открытого файла и, для `.dll`, `.exe`, `.sys`, просмотр модулей доступных процессов. Последний помогает увидеть DLL, загруженные в игровые процессы, например модули RTSS. Нативный запрос класса 47 зарезервирован Windows для системного использования: его отказ показывается как примечание, остальные методы продолжают работать.

DLL может открывать другой файл, но её код выполняется внутри процесса: владельцем открытого файла будет этот процесс. Текущий поиск определяет процесс-владелец; он не определяет, какая именно DLL внутри него вызвала открытие другого файла. Служба также работает в процессе: собственном или общем, например `svchost.exe`. Если проверяемый файл сам является DLL, поиск показывает процессы, которые её загрузили.

Защищённые процессы, драйверы ядра и процессы на удалённом файловом сервере могут быть недоступны даже администратору. Модули проверяются по имени и нормализованному пути; загрузка через жёсткую ссылку с другим именем может не обнаруживаться этим методом. Не все источники гарантируют полный список. Примечания о неполной проверке включаются в отчёт.

Поиск выполняется в отдельном скрытом процессе. Отмена, Esc или истечение минуты прекращают только этот процесс проверки; окно остаётся доступным.

Первый запуск может занять немного больше времени: встроенная среда .NET извлекает нативные компоненты в стандартный временный каталог. EXE не подписан цифровым сертификатом.

## Сборка и проверка

Требуется установленный .NET SDK 10 и Windows x64. В PowerShell из каталога исходников:

```powershell
.\build.ps1 -Test
```

Скрипт создаёт значок, собирает EXE и запускает проверки с реальными отдельными процессами: обычная и исключительная блокировки, два владельца, разрешённое совместное удаление, загруженные 32- и 64-битные DLL, обновление после освобождения, Unicode, кавычки, атрибуты, неверные пути, отмена и элементы интерфейса. Проверки контекстного меню временно регистрируют пункт для текущего пользователя и восстанавливают прежнее состояние реестра. Запуск через Windows Shell, повторное использование и восстановление окна, смена файла во время поиска, обмен сообщениями и передача окна при перезапуске проверяются автоматически; интерактивное подтверждение UAC в тестах не выполняется. Тестовые окна находятся вне экрана. Результаты и изображения интерфейса находятся в `artifacts`.

Документация Windows: [RmGetList](https://learn.microsoft.com/en-us/windows/win32/api/restartmanager/nf-restartmanager-rmgetlist), [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [EnumProcessModulesEx](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-enumprocessmodulesex), [FILE_INFORMATION_CLASS](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_file_information_class).
